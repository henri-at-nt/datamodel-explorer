# Proposal

## Why

The data-model explorer exists as a one-off HTML file generated by Python scripts. Every refresh needs a
manual regeneration, pages cannot be bookmarked, and it cannot grow into something that shows example data
or charts. A small local web app that reads the model directly removes those limits.

## What Changes

- Serve the explorer from a local Node.js server that reads the data-model-content clone directly.
- Compute the model on request and cache it; rebuild only when the model files changed (checked at most once a minute).
- Provide the same views as the HTML file: namespace navigation, store (ClickHouse) overview with hover details and zoom, table pages with filters, relationship diagrams, enums, storage mappings, cross-links between tables and across namespaces.
- Give every namespace and table a real URL.
- Add a global search across tables, fields and enums.
- Port the Python generators to the server and retire them once their output has been verified identical.

## Capabilities

### New Capabilities
- `model-source`: where the model files come from and when the served model is refreshed.
- `model-api`: the read-only HTTP interface that exposes the model.
- `navigation-and-routing`: namespace and table navigation, URLs, and cross-namespace links.
- `store-overview`: the per-namespace overview of Kafka topics, NQL tables and ClickHouse tables.
- `table-detail`: the page for one table, with filters, fields, structured fields, enums and storage.
- `relationship-diagram`: the diagram of what one table relates to.
- `search`: finding tables, fields and enums by name, label or description.

### Modified Capabilities

## Impact

- New repository content: Node server, web app, tests, OpenSpec files.
- Reads (never writes) a local clone of data-platform.data-model-content; no model content is stored in this repository.
- No authentication, no example data and no charts in this change (see the `example-data` change).
